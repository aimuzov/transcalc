# Справочник направлений

Снимок от 14 ноября 2026 года: проверены 249 хостов, найдены 145 региональных прайсов и 33 829 опубликованных направленных пар. Итоговый калькулятор содержит 33 829 доступных пар с учётом отдельных ответов и исключений доступности. Подтверждены 149 региональных ставок и 44 наблюдаемых исключения; ещё 6 121 пара регионов ожидает проверки. Очередь сохранена, дальнейший сбор остановлен.

Калькулятор хранит точную базовую цену каждой собранной пары городов. Направления независимы: цена обратно может отличаться. Весовые категории, сборный груз и НДС рассчитываются по [восстановленной формуле](regional-formula.md).

Базовая цена из таблицы уже включает специальные тарифы направления. Поэтому расчёт не зависит от того, удалось ли отдельно подтвердить региональную ставку за километр. Неизвестные пары не получают приблизительную цену.

## Источники и проверка

`data/catalog/published-rates.json` -- четыре опубликованные цены каждой строки и адрес страницы.
`data/catalog/manifest.json` -- результаты обхода, даты загрузки, SHA-256 страниц, конфликты и пробелы покрытия.
`data/catalog/cities.json` -- названия городов для интерфейса.
`data/moscow-tariffs.json` -- первоначальный снимок, включая индивидуальные страницы направлений.
`data/catalog-provenance.json` -- источники каждого тарифа итоговой базы.
`src/frontend/data/tariffs.json` -- итоговый справочник для браузера.

Сборщик проверяет домен, canonical и город в заголовке. Перенаправление на Москву не становится прайсом другого города. Таймаут, ответ 410 и отсутствие опубликованной строки сохраняются отдельно: ни один из них сам по себе не доказывает, что перевозчик не обслуживает маршрут.

Сборка останавливается при конфликте цен одной пары или отклонении опубликованных весовых коэффициентов. `npm run test:catalog` сверяет все четыре цены каждой сохранённой строки через рабочий калькулятор. Контрольные ответы исходного калькулятора проверяются отдельно.

Если сохранённый расчёт явно возвращает `not_served`, маршрут исключается из доступных даже при наличии цены в таблице. Исходная цена и ответ сохраняются в `data/catalog/availability.json` для проверки расхождения.

## Обновление

Сбор выполняется последовательно, с паузой не меньше секунды и общим HTTP-lock для двух сборщиков. Кеш позволяет продолжить прерванный обход.

```sh
python3 scripts/collect_full_catalog.py --output /tmp/transcalc-full-catalog --hosts data/catalog/hosts.json --probe-target-hosts --resume --retry-failed
```

`--refresh` заново загружает и успешные страницы. Без него дата кешированного ответа сохраняется. Дата на сайте берётся из фактических дат исходных снимков, а не из времени запуска сборки.

После проверки результатов нужно перенести `rows.json` в `data/catalog/published-rates.json`, `manifest.json` в `data/catalog/manifest.json` и обновить канонические названия городов. Затем собрать и проверить базу:

```sh
python3 scripts/build_catalog.py data/catalog/published-rates.json --cities data/catalog/cities.json --manifest data/catalog/manifest.json
python3 scripts/build-route-details.py
npm run test:catalog
npm test
```

## Границы покрытия

Полный обход опубликованных региональных таблиц отличается от перебора всех возможных пар городов. Для пары без опубликованной цены нужен отдельный ответ исходного калькулятора. Если его нет, интерфейс сообщает об отсутствии тарифа в локальном справочнике.

Подтверждённые ставки за километр и найденные исключения сохраняются отдельно от арифметических кандидатов. НОД опубликованных баз может помочь выбрать следующую проверку, но не доказывает ставку: минимальная цена и специальные тарифы нарушают эту закономерность. Кандидаты в расчёте не используются.
