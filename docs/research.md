# Как восстановлен расчёт

Калькулятор работает локально по снимку тарифов datrans.ru от 14 ноября 2026 года.
Запросов к datrans.ru при расчёте нет.
Первая версия охватывает опубликованные направления Москвы и обратно; произвольные пары других городов не поддерживаются.

## Источники

В [сводном прайсе](https://datrans.ru/gruzoperevozki-po-rossii/) есть отдельные таблицы двух направлений.
Они содержат 357 ставок: 136 из Москвы и 221 в Москву.
Индивидуальные страницы `/tariffs/<city>/` дополняют прайс: Москва => Алма-Ата и Москва => Курчатов есть только на отдельных страницах.
После проверки всех 222 адресов в снимке 359 направлений и 223 города, включая Москву.
Скрипт `scripts/collect_tariffs.py` объединяет оба источника, сохраняет снимок, дату и SHA-256 исходного сводного HTML.
Сами HTML-страницы кешируются за пределами репозитория: формы и сторонние скрипты не нужны для расчёта.

Страница [калькулятора](https://datrans.ru/calc/) встраивает объект `DATA` с результатом и диагностикой.
Упомянутый в её коде `/calc/v2/result.php` возвращал `410 Gone`; рабочего API по этому адресу нет.
Исходный серверный код недоступен: ниже описана модель, восстановленная по наблюдениям.

## Отдельная машина

База B: цена машины 20 т для конкретного направления.
Обратный маршрут имеет свою базу.
Вспомогательный `price_per_km` уже округлён и не заменяет B.

| Верхняя граница веса, кг | Множитель B |
| ------------------------ | ----------- |
| 1500                     | 0.44        |
| 3000                     | 0.53        |
| 5000                     | 0.66        |
| 7000                     | 0.75        |
| 10000                    | 0.88        |
| 20000                    | 1           |

Цена округляется вверх до 100 ₽.
При наличии опубликованных цен отдельных классов используются именно они.
Категория 10 т заканчивается на 10000 кг, хотя серверное описание машины допускает 11000 кг.

## Сборный груз

Промежуточная сумма P = B × вес / 10000.
Скидка выбирается по сумме, не по весу:

| Значение P   | Множитель |
| ------------ | --------- |
| менее 20000  | 1.40      |
| менее 40000  | 1.19      |
| менее 60000  | 1.12      |
| менее 100000 | 1.05      |
| менее 140000 | 0.98      |
| остальные    | 0.70      |

Результат округляется вверх до 100 ₽, минимум 12000 ₽.
Затем применяется предел: 85% цены отдельной машины, округлённые вниз до 100 ₽.
Из-за переключения скидки цена иногда уменьшается при увеличении веса; это поведение исходного калькулятора сохранено.

Доступный диапазон: 500...20000 кг; сборный груз предлагается до 11000 кг включительно.
Исходный сервер отбрасывает дробную часть килограммов.
Цена без НДС: округление цены с НДС / 1.22 до целого рубля.
Контейнерные ставки отдельные, не выводятся из B; их режим без НДС отсутствует в исходных ответах.

## Проверка

В `data/training/` сохранены 90 исходных расчётов, включая соседние килограммы у порогов, дробные веса и точные равенства всем денежным порогам.
Дополнительная серия `data/control/` содержит 14 расчётов: другие направления, Казахстан, контейнеры и превышение веса. `node scripts/verify-quotes.mjs` сверяет модель и итоговые локальные тарифы с этими ответами.
На момент фиксации отчёта: 90 совпадений обучающей серии, 14 контрольной, расхождений нет.

## Ограничения

Снимок не обновляется сам.
Точность всей базы не доказывается проверкой нескольких маршрутов: проверены формула и контрольные примеры, остальные базовые ставки взяты из опубликованных таблиц.
Прайс и калькулятор могут обновляться независимо.
Контейнерные ставки подтверждены только для Москвы => Иркутска, Хабаровска и Владивостока.
География расстояний и сроков заполнена только там, где есть сохранённый ответ калькулятора; отсутствующие значения не придумываются.
Цена предварительная, финальную ставку согласует перевозчик.

## Воспроизведение

```sh
python3 scripts/collect_tariffs.py --index-only --output src/frontend/data/tariffs.json
python3 scripts/collect_tariffs.py --delay 1
python3 scripts/collect_tariffs.py --index-only --output src/frontend/data/tariffs.json
python3 -m unittest discover -s scripts -p 'test_*.py'
node scripts/verify-quotes.mjs
npm test
```

Для сбора требуется сеть.
Кеш по умолчанию находится в `/tmp/transcalc-pages`.
Дата снимка берётся из фактических дат загрузки источников, повторное чтение кеша её не обновляет.
Для старого кеша без метаданных используется дата изменения файла; `--refresh` загружает источники заново.
`python3 scripts/build-route-details.py` восстанавливает сведения о сроках и контейнерах из сохранённых ответов.
Последний проход объединения включает доступные индивидуальные страницы из кеша.
Контрольные JSON зафиксированы в Git и не перезаписываются сбором тарифов.
